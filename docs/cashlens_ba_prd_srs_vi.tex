\section{Tóm tắt điều hành}
\begin{summarybox}{Executive Summary}
CashLens là hệ thống quản lý tài chính cá nhân tập trung vào việc tự động đọc email thông báo giao dịch ngân hàng, trích xuất giao dịch, phân loại thu/chi, tổng hợp dashboard theo tháng và hỗ trợ người dùng ra quyết định tài chính. Điểm khác biệt của sản phẩm không chỉ nằm ở tracking quá khứ, mà còn ở các module \textbf{dự định tài chính}, \textbf{smart alerts}, \textbf{in-app notification tự build} và \textbf{AI insight}.
\end{summarybox}

\subsection{Vấn đề nghiệp vụ}
Người dùng thường có nhiều giao dịch ngân hàng nhưng không nhập tay đều đặn vào app quản lý chi tiêu. Email ngân hàng đã chứa dữ liệu quan trọng như số tiền, thời gian, nội dung, số dư, nhưng dữ liệu này đang nằm rải rác trong inbox. CashLens tận dụng email như một nguồn dữ liệu bán tự động để chuyển thành transaction chuẩn hóa.

\subsection{Giải pháp đề xuất}
\begin{enumerate}
  \item User kết nối email bằng OAuth và chọn chính xác ngân hàng/sender được phép lắng nghe.
  \item Hệ thống sync email, match listen rule, lưu metadata, parse giao dịch bằng parser template có version.
  \item Transaction được chuẩn hóa, deduplicate, phân loại bằng rule trước; sau đó có thể bổ sung ML/LLM.
  \item Dashboard hiển thị thu, chi, net income, savings rate, breakdown category, trend theo ngày/tháng.
  \item Module planning giúp user tạo dự định như mua xe, so sánh trả hết/trả góp, đánh giá khả thi.
  \item Alert engine tự build chủ động cảnh báo budget, giao dịch lớn, cashflow risk và goal risk.
\end{enumerate}

\subsection{North Star Metric}
\begin{notebox}{North Star Metric đề xuất}
\textbf{Tỷ lệ giao dịch tài chính được hệ thống tự động tracking và phân loại đúng mỗi tháng trên mỗi user.}
\end{notebox}

\subsection{Quy tắc thiết kế database}
\begin{itemize}
  \item Bảng business nên có \code{id}, \code{created_at}, \code{updated_at}, \code{deleted_at} nếu cần soft delete.
  \item Dùng \code{metadata jsonb} cho field ít ổn định hoặc provider-specific.
  \item Không dùng transaction table để lưu raw email. Tách source layer và finance layer.
  \item Transaction nên lưu \code{source_type}, \code{source_id}, \code{transaction_code}, \code{classification_source} để scale và debug.
  \item Dữ liệu tài chính phải tính bằng backend deterministic logic, không dựa vào LLM.
\end{itemize}

\subsection{Decision engine phân loại}
\begin{notebox}{Luồng đề xuất}
1. Nếu match user rule confidence cao: apply category, source=rule.\newline

3. Nếu ML confidence thấp và user cho phép AI: gọi LLM với payload đã mask/normalize.\newline
4. Nếu vẫn thấp: set transaction status=\code{needs_review}.
\end{notebox}

\section{Chiến lược Alert và Notification tự build}

\subsection{Nguyên tắc thiết kế}
\begin{itemize}
  \item \textbf{Alert engine} là business logic của CashLens, nên thuộc hệ thống của mình.
  \item \textbf{Notification delivery} là lớp gửi thông báo, có thể tự build hoặc đổi provider sau.
  \item MVP chỉ cần \textbf{in-app} và \textbf{email fallback}. Push/Novu để phase sau.
  \item Payload gửi qua email/push không nên chứa quá nhiều thông tin nhạy cảm.
  \item Luôn có cooldown để tránh spam user.
\end{itemize}

\section{Kết luận}
CashLens nên được triển khai như một hệ thống pipeline tài chính thay vì chỉ là CRUD transaction. Điểm quan trọng nhất là tách rõ source layer, parser layer, finance layer, analytics layer và notification layer. Với định hướng tự build alert/notification, sản phẩm vừa giữ được tính chuyên nghiệp, vừa tránh phụ thuộc sớm vào Novu/Push khi core business chưa ổn định.

\begin{summarybox}{Recommendation cuối}
\textbf{MVP:} Auth + transaction manual + dashboard + Gmail connection + listen rules + parser + classification rule.\newline
\textbf{P1:} Budget + alert engine + in-app notification + email fallback + financial goals.\newline
\textbf{P2:} ML classifier + LLM insight + scenario planning + Elasticsearch/Kibana optional.\newline
\textbf{Nguyên tắc:} Backend deterministic logic tính số tiền; AI chỉ hỗ trợ phân loại, giải thích và insight.
\end{summarybox}
